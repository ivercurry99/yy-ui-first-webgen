# UI 设计提示词模板

> 阶段 B 使用。目的：把「高级、科技感、有设计感」这类 AI 听不懂的空词，翻译成它一听就能执行的描述。

## 1. 生成 UI 提示词模板

以「多年经验 UI/UX 设计师」身份，按下面清单逐项写死（写不出的项用行业默认值并声明）：

```
请作为资深 UI/UX 设计师，根据以下页面结构设计 <网站类型> 的首页 UI：

【整体风格】
- 主色调 / 辅助色 / 强调色（给出具体色值或明确描述，如"深蓝 #1B2A4A + 橙色强调"）
- 页面基调：深色 / 浅色 / 深浅混合（首屏深、内容区浅）
- 整体气质：用具体参照描述（如"工业重型感，接近 Caterpillar 官网"），不用"高级感"

【页面布局】
- 内容区最大宽度：<如 1200-1440px>
- 首屏 Banner：<左右两栏 / 全屏大图 / 异形构图>，高度约 <px 或视口占比>，视觉焦点是 <什么>
- 内容区分几屏，每屏放什么模块，排列方式（栅格列数）

【组件规格】
- 卡片：<形状（直角/圆角 px）、有无阴影、边框、内部结构（图上文下/左图右文）>
- 按钮：<形状（圆角 px）、主按钮/次按钮配色、悬停态>
- 导航栏：<高度、透明/实底、毛玻璃与否>

【文字层级】
- 标题 / 副标题 / 正文 / 辅助说明 的字号与字重关系（相对层级即可）

【视觉装饰】
- 背景：纯色 / 渐变 / 纹理 / 几何装饰（写清位置和密度）
- 特殊元素：<玻璃拟态 / 3D 模型展示区 / 发光线条 / 主题化装饰，有则写清放哪，没有写"无">
- 装饰密度：克制留白 / 中等 / 丰富（多轮调整时主要动这项）

【移动端】
- 布局如何折叠：<如"多列卡片变单列，Banner 缩短为 60vh，导航折叠为汉堡菜单">
```

## 2. 多轮修正指令写法

第一版 UI 只判断**方向**：布局对不对、配色对不对、视觉层级对不对、核心内容够不够突出。不追求一次完美。

**修正指令必须具体，禁止模糊词**：

| ❌ 模糊（禁止） | ✅ 具体（要求） |
|---------------|---------------|
| "再高级一点" | "降低颜色数量到 3 个以内，提高留白，去掉装饰性渐变" |
| "Banner 再有设计感一点" | "Banner 不要左右两栏，改全屏大图 + 底部异形切割，主视觉占比 70%" |
| "卡片换一下" | "卡片从直角改 8px 圆角，去掉阴影改 1px 边框，缩略图比例从 16:9 改 4:3" |
| "再像一点" | "导航栏高度从 80px 降到 64px，标题离左边界太远，向左收 40px" |
| "页面太花了" | "减少装饰，提高留白，背景装饰只保留左上角一处" |

**多轮上限建议**：方向类修正通常 2-4 轮可锁定。超过 5 轮仍未锁定 → 停下来和用户对齐问题出在哪一层（布局/配色/组件），而不是继续盲改。

## 3. 锁定标准

同时满足才算锁定：

1. 用户明确说过「OK / 就这样 / 确认」；
2. 页面结构单上的每个模块在 UI 图里都有落位；
3. 配色、布局、组件规格三项无未决分歧。

锁定后 UI 图存为 `assets/ui/reference/home.<png/jpg>`（多页则每页一张），作为阶段 D/E 的对比基准。**锁定后 UI 图不再大改**；开发中发现的视觉问题走阶段 E 的量化修正，不回炉重画。
