# 素材拆分标准与降级方案

> 阶段 C 使用；§3 降级方案在能力缺失时使用。

## 1. 为什么必须拆素材

AI 代码模型再强，也不可能凭空还原截图里的图片资源——背景装饰、3D 物体、光效、纹理、异形卡片、图标。这些全部用 CSS 硬画，结果必然和原稿差距大。把复杂视觉素材单独拆出来，开发时直接调用真实素材，还原度自然高。

## 2. 判断标准

### 不拆（CSS 容易做，让前端写）

- 纯色卡片、圆角、阴影
- 简单线条、分割线、简单几何形
- 单色图标（可用图标库替代）
- 纯色/简单渐变背景

### 必拆（单独出文件）

- 产品主体图片、人物图片
- 3D 模型截图 / 复杂机械结构图
- 复杂装饰元素、异形卡片底图
- 特殊背景、复杂纹理
- 特殊发光图形、光效

### 拆分纪律

1. **一个素材一个文件**——绝不把十几个素材拼在一张 PNG 里，否则开发时无法定位调用。
2. **PNG 透明背景**优先（需要不透明的背景图除外）。
3. 存放目录统一 `assets/ui/`，按页面分组：`assets/ui/home/`、`assets/ui/detail/`。
4. **逐区域过一遍 UI 图，不要凭印象**：首屏 Banner 主视觉、内容卡片里的产品图/人物图、特殊装饰图形、发光元素——每一处都问一句「这个 CSS 画得出吗」，画不出的进清单。
4. 产出《素材清单》（`assets/ui/manifest.md`），每行一条：

```markdown
| 文件 | 页面位置 | 用途 | 建议尺寸 |
|------|---------|------|---------|
| assets/ui/home/hero-machine.png | 首屏 Banner 右侧 | 挖掘机主体 3D 渲染 | 1200x900 |
| assets/ui/home/deco-circuit.png | 首屏背景左上 | 电路纹理装饰 | 600x600 |
```

## 3. 降级方案

### 3.1 无图像生成能力

UI 效果图降级为**文字版设计规格书**（`docs/ui-spec.md`）：

- 按 ui-prompt-template.md §1 的同一份清单逐项写死（色值、宽度、高度、圆角、间距全部给数）；
- 开发阶段严格照规格书执行，"高还原"的对象从 UI 图变成规格书；
- 阶段 E 对比验收改为逐项核对规格书数值与实际代码（间距、色值、字号可从代码里直接读）。

### 3.2 无素材拆分能力（有 UI 图但切不出素材文件）

- 开发阶段所有必拆素材位置使用**占位块**（纯色块或标注尺寸的 placeholder 图）；
- 生成《素材 TODO 清单》（`assets/ui/TODO.md`）：每处需要什么图、建议尺寸、参考 UI 图上的位置；
- 交付时明确提醒用户：占位块需替换为真实素材，替换时保持代码中预留的尺寸/位置。

### 3.3 通用降级原则

任何能力缺失都**不中断流程**：声明缺什么 → 启用对应降级方案 → 在最终交付说明里写明"本次使用了降级方案 <X>，影响：<Y>"。
